title: Response Shapes
description: The default response is already simple. Pass detail=full only when you need advanced signals.
---

The default API response is already a tight 8-field shape. There is no separate "simplified" mode — the default IS the simplified mode.

## Default response (8 fields)

```json
{
  "verdict": "ai",
  "confidence": 0.91,
  "origin": "suno",
  "origin_confidence": 0.82,
  "risk_timeline": [0.12, 0.14, 0.88, 0.91, 0.89, 0.87],
  "duration_sec": 187.4,
  "model_version": "2026-04-29",
  "processed_at": "2026-04-29T10:43:01Z"
}
```

Returned by:
- `POST /api/analyze` (single-track, polled via `GET /api/jobs/{job_id}/status`)
- `GET /bulk/jobs/{job_id}/results` (NDJSON, one record per line, with an extra `item_id`)

| Field | Type | Description |
|-------|------|-------------|
| `verdict` | `"ai"` \| `"human"` \| `"uncertain"` | Final classification |
| `confidence` | float (0–1) | Confidence in the verdict |
| `origin` | string \| null | Detected generator when AI |
| `origin_confidence` | float (0–1) \| null | Confidence in origin attribution |
| `risk_timeline` | float[] | Per-window AI probability (~2.5s windows) |
| `duration_sec` | float | Audio duration in seconds |
| `model_version` | string | Detector calibration version |
| `processed_at` | string (ISO 8601 UTC) | When analysis completed |

## `?detail=full` (adds 3 blocks)

Pass `?detail=full` to extend the response with `scores`, `risk_segments`, and `tier_verdicts`:

```json
{
  "scores": {
    "spectral": 0.91,
    "temporal": 0.77,
    "representation": 0.68,
    "geometry": 0.79,
    "reliability": 0.88
  },
  "risk_segments": [
    { "start": 0.0, "end": 2.5, "risk": 0.12 },
    { "start": 2.5, "end": 5.0, "risk": 0.88 }
  ],
  "tier_verdicts": {
    "press_safe": "uncertain",
    "human_safe": "ai",
    "recall": "ai"
  }
}
```

The 8 default fields are still present; `detail=full` only **adds** to the response, never renames or rescales.

## Consistency guarantees

- **Verdict taxonomy.** `verdict` and every value inside `tier_verdicts` is one of `"ai"`, `"human"`, or `"uncertain"`. No other strings.
- **Confidence scale.** Always 0.0–1.0, never percent.
- **Timestamps.** Always ISO 8601 UTC.
- **Same shape on single and bulk.** A bulk record is identical to the single-track response, plus an `item_id` field.

## Routing

```python
def route(record: dict) -> str:
    if record.get("status") == "failed":
        return "manual_review"
    if record["verdict"] == "ai":
        return "reject"
    if record["verdict"] == "uncertain":
        return "manual_review"
    return "approve"
```

For threshold-based gating, combine `verdict` with `confidence`:

```python
if record["verdict"] == "ai" and record["confidence"] >= 0.85:
    return "reject"
```

For three operating points (strict, default, lenient) in one request, read `tier_verdicts` from `?detail=full`. See [Confidence Tiers](/guides/confidence-tiers).

## Failures

Bulk records on failure include `status: "failed"` plus error fields:

```json
{
  "item_id": "track-005",
  "status": "failed",
  "error": "Could not download audio: access denied (403). Ensure the URL is publicly accessible.",
  "error_code": "source_forbidden"
}
```

| Code | Meaning |
|------|---------|
| `source_forbidden` | 403 — the URL requires authentication |
| `source_not_found` | 404 — the file was not found |
| `source_unauthorized` | 401 — the URL requires credentials |
| `timeout` | Analysis timed out |
| `no_workers_available` | GPU capacity temporarily exhausted — retry shortly |
| `audio_decode_error` | The file is not a valid audio format |
| `analysis_error` | Catch-all for other failures |
