## The result record

```json
{
  "verdict": "ai",
  "confidence": 0.91,
  "origin": "suno",
  "origin_confidence": 0.82,
  "risk_timeline": [0.12, 0.14, 0.88, 0.91, 0.89, 0.87],
  "duration_sec": 187.4,
  "model_version": "2026-04-29",
  "processed_at": "2026-04-29T10:43:01Z"
}
```

Bulk records add `item_id` (the identifier you supplied at submit time). Everything else is identical.

## Key fields

| Field | What it's for |
|-------|--------------|
| `verdict` | Final classification — `"ai"`, `"human"`, or `"uncertain"` |
| `confidence` | Confidence in the verdict (0–1). Use for display and threshold-based routing |
| `origin` | Predicted generator when AI: `"suno"`, `"udio"`, `"elevenlabs"`, etc. |
| `origin_confidence` | Confidence in origin attribution (0–1) |
| `risk_timeline` | Per-window AI probability across the track. Shows which sections triggered |
| `duration_sec` | Audio duration in seconds |
| `model_version` | Detector calibration version. Include in audit records |
| `processed_at` | When analysis completed (ISO 8601 UTC) |

## Routing on `verdict`

```python Python
def route(record: dict) -> str:
    if record["verdict"] == "ai":
        return "reject"
    if record["verdict"] == "uncertain":
        return "manual_review"
    return "approve"
```

```typescript TypeScript
function route(record: Record<string, any>): string {
  if (record.verdict === "ai") return "reject";
  if (record.verdict === "uncertain") return "manual_review";
  return "approve";
}
```

For threshold-based routing (e.g. only reject when `confidence >= 0.85`), gate on `confidence` alongside `verdict`.

## Tier verdicts (advanced)

If you need different operating points — e.g. a strict gate for press releases and a permissive gate for internal review — pass `?detail=full` and read `tier_verdicts`:

```json
{
  "tier_verdicts": {
    "press_safe": "uncertain",
    "human_safe": "ai",
    "recall": "ai"
  }
}
```

| Tier | Use it for |
|------|-----------|
| `press_safe` | Press-chain default gate, certification, licensing submissions |
| `human_safe` | Distribution-layer auto-reject at intake |
| `recall` | Escalation to manual review |

Each tier uses the same `ai` / `human` / `uncertain` taxonomy as top-level `verdict`. See [Confidence Tiers](/guides/confidence-tiers) for the false-positive rate at each tier.

## Handling failures

Bulk records may include a `status` field. On failure, `verdict` is absent and `error` / `error_code` describe what went wrong:

```json
{
  "item_id": "track-005",
  "status": "failed",
  "error": "Could not download audio: access denied (403). Ensure the URL is publicly accessible.",
  "error_code": "source_forbidden"
}
```

| Code | Meaning |
|------|---------|
| `source_forbidden` | 403 — the URL requires authentication |
| `source_not_found` | 404 — the file was not found at that URL |
| `source_unauthorized` | 401 — the URL requires credentials |
| `timeout` | Analysis timed out |
| `no_workers_available` | GPU capacity temporarily exhausted — retry shortly |
| `audio_decode_error` | The file is not a valid audio format |
| `analysis_error` | Catch-all for other failures |

Always route failed tracks to manual review — never auto-reject on an analysis failure.
